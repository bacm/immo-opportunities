# v0.7 — MVP connecté

**État :** Implémenté — activation sur candidats réels bloquée par la publication v0.6  
**Dépend de :** v0.4 et v0.6

## Objectif utilisateur

Explorer, comprendre, simuler et qualifier un candidat réel de bout en bout dans un espace d’organisation sécurisé.

## Inclus

- Explorer carte/liste/fiche connecté aux API et tuiles réelles ;
- filtres MVP et pagination par curseur ;
- scénarios financiers personnalisables sans modifier les sources ;
- Keycloak OIDC Authorization Code + PKCE ;
- organisations, utilisateurs et rôles ;
- RLS sur les tables privées ;
- favoris, statuts, notes, revues et motifs de rejet ;
- historique immuable des changements de statut ;
- administration minimale des imports et de la qualité ;
- client TypeScript généré depuis OpenAPI ;
- observabilité corrélée API, workers et pipelines ;
- frontend mobile minimal pour consulter, changer un statut et prendre une note.

## Hors périmètre

- alertes, collaboration avancée et CRM ;
- indice de vacance ;
- prospection automatisée ;
- exports contenant des données non autorisées ;
- France entière.

## Remplacement des fixtures

Les données simulées créées pour la première maquette sont supprimées du chemin de production. Si elles restent utilisées en tests ou Storybook, elles sont isolées sous `fixtures` et impossibles à activer en production.

## Actions API

- `POST /api/v1/opportunities/{id}/reviews`
- `PATCH /api/v1/opportunities/{id}/status`
- `POST /api/v1/opportunities/{id}/notes`
- `POST /api/v1/opportunities/{id}/scenarios`
- `POST /api/v1/saved-searches`
- `GET /api/v1/admin/import-runs`
- `GET /api/v1/admin/data-quality`

## Sécurité et confidentialité

- toutes les requêtes privées portent l’organisation courante ;
- RLS fournit une défense supplémentaire ;
- les exports et consultations sensibles sont audités ;
- les notes et scénarios ne sont jamais placés dans les tuiles communes ;
- les messages produit reprennent les limites de la spec ;
- les sources et la confiance ne sont pas masquées par le niveau d’offre.

## Tests obligatoires

- parcours Playwright recherche → fiche → scénario → statut → note ;
- séparation stricte entre deux organisations ;
- rôles et refus d’accès ;
- refresh et expiration de session OIDC ;
- synchronisation URL/carte/liste/fiche ;
- valeurs inconnues distinctes de zéro ;
- historisation avec auteur et date ;
- budget de performance des écrans critiques ;
- accessibilité clavier et audit automatisé ;
- erreurs API, source indisponible et snapshot périmé.

## Critères d’acceptation

- toutes les exigences `FR-001` à `FR-012` sont reliées à au moins un test ;
- un utilisateur qualifie un candidat sans donnée simulée ;
- le scénario est recalculé sans modifier le snapshot ;
- un utilisateur d’une organisation ne lit aucune donnée privée d’une autre ;
- les états obligatoires de l’Explorer sont visibles ;
- les objectifs NFR du MVP sont mesurés.

## Démonstration attendue

Se connecter, rechercher une adresse, filtrer des opportunités, examiner preuves et comparables, modifier un scénario, retenir le candidat, ajouter une note, puis vérifier l’historique.

## Risques

- dupliquer les modèles API manuellement dans le frontend ;
- laisser l’organisation être choisie depuis un paramètre non fiable ;
- coupler les annotations utilisateur aux snapshots communs ;
- masquer les données inconnues pour simplifier l’interface.
