# v0.1 — Foundation

**État :** Bloquée (preuve CI GitHub uniquement)  
**Dépendances :** aucune

## Objectif utilisateur

Disposer d’un environnement reproductible sur lequel les prochaines versions peuvent importer des données, exposer une API et faire évoluer le frontend sans installation manuelle implicite.

## Inclus

- monorepo `apps`, `backend`, `pipelines`, `contracts` et `map` ;
- workspace Python 3.13 géré par `uv` ;
- FastAPI sous `/api/v1` avec erreurs structurées et identifiant de requête ;
- SQLAlchemy 2, psycopg 3, GeoAlchemy2 et Alembic ;
- schémas PostgreSQL `meta`, `reference`, `observation`, `feature`, `scoring`, `market`, `app`, `tiles` et `audit` ;
- rôles PostgreSQL minimaux définis par l’architecture ;
- squelette Dagster avec une code location et un asset de diagnostic ;
- frontend React existant intégré au workspace et servi par Caddy ;
- services `api`, `martin`, `dagster-webserver`, `dagster-daemon` et `dagster-code` dans Docker Compose ;
- lint, typecheck, tests et build dans la CI ;
- génération ou validation du contrat OpenAPI.

## Hors périmètre

- import d’un dataset immobilier réel ;
- authentification utilisateur complète ;
- score métier ;
- tuiles contenant de vraies entités.

## API

- `GET /health/live`
- `GET /health/ready`
- `GET /api/v1/meta/version`
- `/docs` désactivable en production

## Tests obligatoires

- démarrage de la stack sur un volume PostgreSQL vide ;
- application et rollback d’une migration de test ;
- tests unitaires backend et pipelines ;
- Ruff, Pyright, `tsc` et build Vite ;
- validation de tous les fichiers Compose ;
- healthchecks Caddy, API, PostgreSQL, MinIO, Redis, Martin et Dagster ;
- contrôle qu’un rôle `tiles_ro` ne peut pas lire les schémas privés.

## Critères d’acceptation

- `make dev` démarre l’environnement documenté ;
- une commande unique exécute tous les contrôles locaux ;
- l’API se connecte à PostGIS et retourne sa version de build ;
- Dagster charge sa code location sans erreur ;
- Caddy sert le frontend et route `/api/*` ;
- aucune configuration sensible n’est inscrite dans une image ou dans Git.

## Démonstration attendue

Depuis un clone propre : démarrer la stack, ouvrir le frontend, appeler l’API de version, ouvrir Dagster, puis exécuter la suite de contrôles.

## Risques

- surinvestir le socle avant un premier import ;
- diverger des versions runtime définies dans l’architecture ;
- donner trop de droits aux rôles techniques.
