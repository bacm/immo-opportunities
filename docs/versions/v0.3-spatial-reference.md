# v0.3 — Référentiel spatial

**État :** En cours  
**Dépend de :** v0.2

## Objectif utilisateur

Pouvoir rechercher et analyser une unité immobilière cohérente plutôt que des géométries isolées.

## Inclus

- DS-02 RNB, DS-03 BDNB Open, DS-04 BD TOPO et DS-05 BAN sur le périmètre 35 ;
- entités `Area`, `Address`, `Parcel`, `Building`, `BuildingParcel`, `PropertyUnit` et `PropertyUnitMember` ;
- conservation de tous les identifiants sources ;
- résolution `Adresse ↔ Parcelle ↔ Bâtiment` ;
- méthode, version et confiance pour chaque `EntityMatch` ;
- gestion explicite des appariements certains, ambigus et rejetés ;
- inspection administrative d’un appariement ;
- première version des features morphologiques indépendantes du marché.

## Hors périmètre

- résolution complète logement/local ;
- score final ;
- usage de prédictions BDNB Expert ;
- déduction d’une intention de vente ou d’une vacance.

## Règles de résolution

Ordre de préférence : identifiant officiel, relation source explicite, intersection spatiale, proximité, adresse normalisée, puis cohérence temporelle.

Un score de match ne doit pas masquer l’ambiguïté. Un appariement critique sous le seuil de publication empêche la production future d’un score.

## Features livrées

- `LAND-001` à `LAND-010` lorsque les sources nécessaires sont acceptées ;
- `BLD-001` à `BLD-003` avec provenance ;
- métriques de complétude et de contradiction utilisées uniquement pour la confiance.

Les valeurs non calculables restent absentes avec un motif. Elles ne deviennent jamais zéro.

## Tests obligatoires

- liens un-à-un, un-à-plusieurs et plusieurs-à-plusieurs ;
- bâtiments couvrant plusieurs parcelles ;
- parcelles contenant plusieurs bâtiments ;
- adresses multiples ou absentes ;
- géométries divergentes entre sources ;
- stabilité des identifiants internes après réimport ;
- tests unitaires de chaque feature morphologique ;
- revue manuelle stratifiée d’un échantillon d’appariements.

## Critères d’acceptation

- aucun identifiant source n’est écrasé ;
- le taux d’appariements certains et ambigus est mesuré par commune ;
- chaque feature expose source, formule, transformation et règle de valeur manquante ;
- un administrateur peut expliquer pourquoi deux entités sont liées ;
- les cas ambigus peuvent être exclus de la publication.

## Démonstration attendue

Rechercher une adresse réelle, afficher sa parcelle, ses bâtiments et leurs sources, puis comparer un appariement certain à un cas ambigu.

## Risques

- prendre un groupe BDNB pour un bâtiment physique unique ;
- double compter une donnée issue de BDNB et de sa source primaire ;
- utiliser la proximité sans seuil adapté au contexte ;
- recréer les identifiants internes à chaque release.
